# 协作写作流程

本流程协调项目管理窗口、大纲窗口、章节窗口、正文写作窗口和作者。

核心原则：

> 对话负责讨论，文件负责交接；任务消息只负责通知。

> 当前责任窗口直接创建下一工作窗口；项目管理窗口不作为每章日常流转的中转站。

## 一、职责

### 项目管理窗口

负责项目初始化、Git版本与恢复点、项目状态和窗口登记的一致性检查、流程维护、经验归并与阶段复盘。不判断具体内容，不代写正文，也不作为每章日常启动和窗口创建的必经入口。

### 大纲窗口

维护全书结构、章节分工和写作规范；作者提出“启动第X章”后，核对全书依据并创建该章空白工作包和章节窗口；同时负责方案审核、写作任务轻量检查和正文终审。不代替章节窗口修改已经接管的章节工作文件。

### 章节窗口

与作者讨论本章，维护章节要求、资料、写作任务、正文审核、最终正文和章节回填。方案通过且写作任务轻量检查通过后创建正文写作窗口，并负责把写作工作稿验收到可以作者审读的程度。

### 正文写作窗口

只根据已经批准的正文写作任务单创作或返修正文工作稿。交稿后通知并返回章节窗口；不修改大纲、任务单、资料状态、章节正文或项目状态中的其他章节。

### 作者

确认创作方向、个人事实、表达声音和最终取舍。作者不负责在窗口间复制完整材料。

## 二、统一交接协议

每个阶段完成后，责任窗口必须连续执行：

1. 写入：把稳定结果写入对应文件；
2. 更新：修改项目状态中的对应行；
3. 通知：按窗口登记通知下一责任窗口；
4. 确认：等待下一窗口读取并确认接管。

通知只写任务、文件位置和期望动作，不粘贴完整材料。

如果下一阶段需要新窗口，由本流程指定的当前责任窗口直接创建。新窗口自行登记准确任务 ID、更新自己负责的状态行并确认接管。作者不复制完整材料，也不为交接手工返回项目管理窗口。

## 三、启动章节

作者说：

> 启动第X章。

这条指令在当前大纲窗口提出。大纲窗口应：

1. 读取项目状态、简版大纲、本章正式大纲、写作规范和必要的前章回填，确认章节可以启动；
2. 检查目标章节目录；不存在时复制 00-章节模板 建立空白工作包，已存在时只核对、不覆盖；
3. 创建本章章节窗口，只发送任务、工作包位置和必须读取的全书依据；
4. 要求新章节窗口自行登记准确任务 ID、更新本章状态并确认接管。

新章节窗口接管后应：

1. 读取上述全书依据、本章工作包、已固化经验和与本章直接相关的待确认经验；
2. 在窗口登记中登记自己；
3. 将项目状态更新为“讨论中”；
4. 整理不超过五项的本章检查项；
5. 与作者讨论，不立即生成正文写作任务单。

探索性讨论不逐轮写入文件。只有稳定共识才进入章节要求或参考资料。

## 四、提交方案审核

作者说：

> 整理当前共识，提交方案审核。

章节窗口应：

1. 更新章节要求；
2. 更新参考资料，区分已核验、待核验、线索和排除项；
3. 建立或更新方案审核单；
4. 把项目状态改为“待方案审核”；
5. 通知当前大纲窗口。

大纲窗口审核：

- 本章功能是否明确；
- 因果链是否成立；
- 是否与其他章节重复或冲突；
- 资料能否支撑关键判断；
- 哪些内容必须保留、移交或删除；
- 完成标准是否可验收。

大纲窗口把意见写入方案审核单。需要修改时，章节窗口把项目状态改为“方案修改中”，按意见处理并提交复核；方案通过后，项目状态改为“方案已通过”。

## 五、启动正文写作

作者说：

> 方案通过，启动正文写作。

这条指令在当前章节窗口提出。

章节窗口应：

1. 根据已批准方案生成正文写作任务单；
2. 将项目状态改为“写作任务待检查”，请求大纲窗口做轻量检查；
3. 轻量检查只核对章节功能、必写内容、跨章边界和资料状态；
4. 检查通过后创建本章正文写作窗口；
5. 在窗口登记中记录准确任务标题和任务 ID；
6. 要求写作窗口读取任务单、参考资料及必要规范；
7. 将项目状态更新为“正文写作中”。

正文写作窗口不得重新设计章节，也不得把待核验资料写成确定事实。

## 六、初稿交付与强制验收

正文写作窗口完成初稿后：

1. 写入正文工作稿；
2. 注明依据的任务单版本；
3. 通知章节窗口；
4. 将项目状态更新为“初稿待验收”。

交稿通知直接发送给当前章节窗口，不经过项目管理窗口。

章节窗口按以下顺序验收：

1. 内容与事实边界；
2. 三至五句话能否概括整章因果链；
3. 每一节是否只有一个主要任务；
4. 每一节是否比上一节新增内容；
5. 材料是否真正承担证明任务；
6. 章末是否只完成本章；
7. 是否占用其他章节。

验收分级：

- A级重写：核心因果链、章节功能或主要内容不成立，由正文写作窗口按结构化要求重写。
- B级返修：主线基本成立，但节间推进、材料安排或整体文气需要集中修改，由正文写作窗口返修。
- C级可审读：结构、资料和跨章边界通过，可以进入作者审读。

审核结论写入正文审核记录。A、B级均由写作窗口处理；章节窗口不以局部润色掩盖结构问题。

- A级时，章节窗口把项目状态改为“A级重写”，通知正文写作窗口；
- B级时，章节窗口把项目状态改为“B级返修”，通知正文写作窗口；
- 写作窗口完成重写或返修后，把项目状态重新改为“初稿待验收”并通知章节窗口；
- C级时，章节窗口把项目状态改为“C级可审读”。

## 七、作者审读

达到C级后：

1. 章节窗口将认可的工作稿纳入章节正文；
2. 正文写作窗口标记阶段任务完成，并由章节窗口将其移入历史窗口；
3. 章节窗口将项目状态改为“作者审读中”，作者与章节窗口进行逐段审读；
4. 章节窗口负责局部表达、作者声音、真实经验和衔接修改；
5. 普通修改不再来回唤醒正文写作窗口；
6. 只有需要整章重构时，才重新启动写作窗口。

## 八、正文终审

作者说：

> 这版正文定稿，完成章节关闭。

这条指令表示“提交正文终审，并在终审通过后自动完成关闭”，不跳过正文终审。章节窗口先将项目状态改为“待正文终审”，再通知大纲窗口。

大纲窗口只检查：

- 是否完成本章任务；
- 是否偏离批准方案；
- 是否与其他章节冲突；
- 是否产生需要同步全书的稳定调整；
- 资料边界是否仍然成立。

逐句润色和作者声音不属于大纲终审职责。

如有必须修改项，章节窗口把项目状态改为“正文终审修改中”，处理后重新提交；终审通过后进入章节自动关闭。

## 九、章节自动关闭

大纲窗口确认正文终审通过后，章节窗口不等待作者追加提醒，自动执行：

1. 保存最终章节正文；
2. 完成章节回填；
3. 在章节回填中记录需要同步全书的稳定调整；如确有调整，通知大纲窗口更新其负责的正式大纲、简版大纲或写作规范，并确认完成；
4. 存在跨章节或长期稳定决策时，更新项目决策记录；
5. 更新项目状态为“待章节关闭”；
6. 提交本章写作与协作经验；
7. 回读确认经验已经实际写入；无新增经验时明确记录；
8. 把被替换的正式版本移入历史归档；
9. 更新项目状态为“已关闭”；
10. 通知项目管理窗口为已关闭章节建立 Git 恢复点，并归并经验、检查冲突。

项目管理窗口完成恢复点和经验归并后，只回传完成结果，不重新接管下一章。下一章仍由作者在大纲窗口提出“启动第X章”。

任一事项未完成，不得宣布章节全部完成。

## 十、经验管理

- 首次出现：待观察；
- 第二次出现或已造成明显损失：待确认；
- 经过实际验证并落入正式规则：已固化；
- 不能通过适用场景化解：冲突待裁定；
- 每完成三至五章或关键窗口换代：阶段复盘。

章节窗口保留现场信息，项目管理窗口负责去重、归类、判断范围和正式落地。

## 十一、窗口换代

任何长期窗口上下文接近上限时，由当前责任窗口为自己创建接班窗口：

1. 更新所负责的正式文件；
2. 填写窗口交接；
3. 创建接班窗口；
4. 要求新窗口读取必要材料；
5. 新窗口登记准确任务 ID；
6. 旧窗口移入历史记录；
7. 新窗口确认接管后，旧窗口停止接收新任务。

重要信息以文件为准，不要求新窗口继承全部聊天历史。

项目管理窗口只在当前责任窗口无法创建接班窗口、登记冲突或原窗口已经不可用时执行异常恢复。

## 十二、作者固定动作

- 启动第X章
- 整理当前共识，提交方案审核
- 方案通过，启动正文写作
- 这版正文定稿，完成章节关闭

其余内部通知和交接由责任窗口自动执行。

作者不需要在每个阶段返回项目管理窗口，也不需要在窗口之间复制完整材料。
