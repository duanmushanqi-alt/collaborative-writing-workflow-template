# 协作写作项目模板

这是一个空白、可复用的长篇写作协作项目。它把项目管理、全书大纲、章节策划、正文写作、审核返修、作者审读、章节回填和经验复盘连接成一套完整流程。

本仓库默认处于“模板模式”，只维护流程和空白模板，不保存任何一本具体作品的内容。

## 核心目标

1. 对话负责讨论，文件负责交接。
2. 大纲、章节策划、正文写作和项目管理分别由不同窗口承担。
3. 正文写作窗口属于项目内部，不依赖外部 AI 或人工搬运材料。
4. 当前状态只有一个来源：00-项目管理/项目状态.md。
5. 每个阶段完成后自动执行“写入、更新、通知、确认”。
6. 作者只做方向、声音和最终取舍，不负责在窗口之间复制材料。
7. 当前责任窗口直接创建下一工作窗口；项目管理窗口不是每章日常启动的中转站。

## 第一次使用

从本模板生成一本新书项目后，在项目管理窗口说：

> 初始化新书项目。

项目管理窗口必须按照 00-项目管理/项目启动清单.md 执行，至少完成：

1. 将项目模式从“模板”改为“正式项目”；
2. 填写项目名称、作者和模板版本；
3. 登记项目管理窗口并创建第一个大纲窗口；
4. 由大纲窗口与作者完成项目定位、第一版正式大纲、简版大纲和写作规范；
5. 由完成阶段任务的窗口更新项目状态，项目管理窗口检查状态与窗口登记的一致性；
6. 由项目管理窗口保存初始化恢复点。

初始化完成后，作者在当前大纲窗口说：

> 启动第X章。

大纲窗口核对全书依据、创建该章空白工作包和章节窗口；新章节窗口自行登记并更新本章状态。作者不需要返回项目管理窗口，也不需要复制完整材料。

## 作者日常只需记住四个动作

1. 启动第X章
2. 整理当前共识，提交方案审核
3. 方案通过，启动正文写作
4. 这版正文定稿，完成章节关闭

窗口之间的创建、登记、通知、审核回传、经验提交和状态同步属于内部流程，不要求作者逐项提醒，也不要求作者在每个阶段手工返回项目管理窗口。

## 模板仓库与书稿项目的边界

- 模板仓库：只修改通用流程、空白模板和说明。
- 书稿项目：保存具体书名、大纲、资料、章节和作者内容。
- 不把书稿项目中的具体内容合并回模板。
- 书稿项目中验证有效的通用方法，可以先匿名总结，再由模板维护者决定是否更新模板。
- 模板升级记录写入 CHANGELOG.md；书稿项目记录自己采用的模板版本，但不必自动追随所有升级。

## 版本恢复点

以下时机应保存一个可恢复版本：

- 项目初始化完成；
- 全书结构发生稳定调整；
- 每章正式关闭；
- 每次阶段复盘完成；
- 全书初稿或统稿阶段完成。

普通句子修改不必单独建立恢复点。
