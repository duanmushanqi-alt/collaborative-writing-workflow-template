# 协作写作项目模板

这是一个空白、可复用的长篇写作协作项目。它把全书结构、章节策划、资料管理、外部写作、审核返修、作者审读、章节回填、经验复盘和版本恢复连接成一套完整流程。

本仓库默认处于“模板模式”，只维护通用流程和空白模板，不保存任何具体作品的书名、大纲、资料或正文。

## 核心原则

1. 对话负责讨论，文件负责交接；任务消息只负责通知。
2. 当前状态只有一个来源：`00-项目管理/项目状态.md`。
3. 每章只保留七类正式文件，过程版本可以覆盖，最终只保留当前认可稿。
4. 方案审核和正文终审分开，提示词只在方案通过后生成。
5. 外部AI、其他写作者或内部写作窗口都可以生产初稿，章节窗口负责统一验收。
6. 作者只做方向、声音和最终取舍，不负责在窗口之间搬运材料。
7. 章节关闭时必须完成回填、经验复盘、状态同步和可恢复版本。

## 文件结构

```text
00-项目管理/      项目设置、唯一状态、窗口登记、协作流程、决策与经验
01-全书控制/      项目定位、正式大纲、简版大纲、写作规范
02-章节工作包/    每章七类文件与空白模板
03-全书资料库/    跨章资料、待核验任务与可选资料寻回模块
90-历史归档/      被替换的重要版本与迁移说明
```

## 第一次使用

从本模板生成新项目后，在项目管理窗口说：

> 初始化新书项目。

按 `00-项目管理/项目启动清单.md` 完成项目身份、窗口、全书控制文件、状态看板和初始化恢复点。然后在当前大纲窗口或新建章节窗口说：

> 启动第X章。

## 作者日常只需记住四个动作

1. `启动第X章`
2. `整理当前共识，提交方案审核`
3. `方案确认，进入写作阶段`
4. `这版正文定稿`

方案返修、提示词轻检、初稿验收、正文终审、章节回填、经验提交、状态同步和恢复点由责任窗口自动完成。只有真实分歧、资料风险或授权问题才提交作者决定。

## 每章七类文件

1. `章节要求.md`
2. `参考资料.md`
3. `方案审核单.md`
4. `外部AI提示词.md`
5. `章节正文.md`
6. `正文审核记录.md`
7. `章节回填.md`

文件职责与关闭检查见 `02-章节工作包/README.md`。

## 模板与具体项目的边界

- 模板仓库只保存通用规则、空白文件和迁移说明。
- 具体项目保存书名、大纲、资料、章节和作者内容。
- 实际项目验证有效的方法，先匿名化、去除作品特征，再更新模板。
- 模板升级记录写入 `CHANGELOG.md`；具体项目不必自动追随所有升级。

## 恢复点

在项目初始化、每章关闭、全书结构重大调整、阶段复盘和全书阶段性完成后建立Git恢复点。普通讨论和小改动不单独备份。

## 从1.x迁移

1.x项目中的 `写作协作/正文写作任务单.md` 可改名或整理为 `外部AI提示词.md`；`正文审核记录.md` 移到章节目录顶层；认可的 `正文工作稿.md` 合并到 `章节正文.md`，旧过程稿按需归档。迁移后删除“正文写作窗口”为必选角色的规则，并将状态映射到2.0的唯一状态表。不要批量覆盖已有正文。
