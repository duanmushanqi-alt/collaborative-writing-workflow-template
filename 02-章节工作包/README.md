# 章节工作包说明

作者在大纲窗口说“启动第X章”后，由当前大纲窗口复制 00-章节模板 并按正式目录编号重命名，再创建章节窗口。已存在的章节目录只核对、不覆盖；未启动章节不提前批量制造空文件。新章节窗口接管后自行登记并更新本章状态。

## 标准结构

    第X章/
      章节要求.md
      参考资料.md
      方案审核单.md
      章节正文.md
      章节回填.md
      写作协作/
        正文写作任务单.md
        正文工作稿.md
        正文审核记录.md

## 文件职责

- 章节要求：章节功能、边界、内容和完成标准。
- 参考资料：资料来源、核验状态和证明任务。
- 方案审核单：大纲窗口对章节方案的审核历史。
- 正文写作任务单：交给内部正文写作窗口的批准任务。
- 正文工作稿：正文写作窗口的当前交付。
- 正文审核记录：章节窗口的A/B/C验收和返修任务。
- 章节正文：已经达到C级并进入作者审读的当前认可版本。
- 章节回填：章节完成后的实际路径、差异、资料和后续避让。

## 所有权

| 文件 | 主要维护窗口 |
|---|---|
| 章节要求 | 章节窗口 |
| 参考资料 | 章节窗口 |
| 方案审核单 | 大纲窗口；章节窗口只填写处理区 |
| 正文写作任务单 | 章节窗口 |
| 正文工作稿 | 正文写作窗口 |
| 正文审核记录 | 章节窗口 |
| 章节正文 | 章节窗口 |
| 章节回填 | 章节窗口 |

## 重要规则

1. 当前阶段只记录在项目状态中。
2. 写作工作稿不能直接覆盖章节正文。
3. 方案未通过，不生成正文写作任务单。
4. 任务单未通过轻量检查，不创建正文写作窗口。
5. 工作稿未达到C级，不进入作者审读。
6. 章节关闭检查未全部完成，不标记为已关闭。
7. 方案通过且任务单轻量检查通过后，由章节窗口创建正文写作窗口。
8. 章节关闭后，由章节窗口通知项目管理窗口建立Git恢复点并归并经验。
